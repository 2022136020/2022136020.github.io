FestaCal페스타콜

전국 축제·공연·전시를 한 곳에서 찾고, 비 예보와 내 위치 기준 추천으로 놓치지 않게 챙기는 반응형 웹 서비스

왜 만들었나

  • 축제 정보가 지자체, 기관마다 따로 있어서 한 번에 비교하기 어렵습니다.
  • 야외 축제가 비 때문에 취소돼도 미리 알기 어려워 헛걸음하게 됩니다.
  • 가고 싶은 축제를 날짜에 맞춰 챙겨 두기가 불편합니다.

그래서

  • TourAPI와 KCISA 공연·전시 정보를 모아 한 곳에서 검색
  • 기상청 단기예보로 실외 행사에 비 소식이 있으면 경고하고 실내 행사를 추천
  • 캘린더에 담으면 D-DAY와 진행 상태를 알아서 계산

내가 한 일

팀장이라 기획서, 계획서, 스토리보드와 일정 관리를 맡았고 백엔드와 프론트 개발도 같이 했습니다. 수업이 끝난 뒤 11월에는 혼자 로그인 방식을 바꾸고 우천 경고를 다시 고쳤습니다.

공공 API는 호출 제한이 있어서 @Scheduled로 주기적으로 받아 DB에 저장해 두고 씁니다.

우천 경고 기준

실외 축제이고, 행사 기간과 예보 범위(오늘~모레)가 겹치는 날 중 하루라도 강수확률이 60% 이상이면 경고합니다. 겹치는 날이 없으면 기상청을 아예 부르지 않습니다.

로그인 바꾼 이유

처음엔 이메일만으로 로그인돼서 탈퇴나 설정 변경을 누가 했는지 확인할 수 없었습니다. BCrypt 비밀번호와 30일 토큰으로 바꾸고, userId를 요청으로 받던 12곳을 전부 토큰으로 본인 확인하도록 고쳤습니다.

그 밖에

  • 늦게 온 예전 응답이 최신 결과를 덮어쓰지 않게 공용 훅(useFetch, usePage)으로 정리
  • Haversine 공식으로 내 위치와의 거리 계산
캘린더 우천 경고가 한 번도 안 뜸11월

원인캘린더 응답이 우천 여부를 항상 false로 보내고 있었고, 판단도 시작일만 봐서 이미 진행 중인 축제는 경고가 안 뜸. 실외 축제는 대부분 몇 달씩 진행되는 거라 사실상 아무 데서도 안 뜨고 있었음

해결행사 기간과 예보 범위가 겹치는지로 다시 짜고 테스트 6개 추가. 진행 중인 실외 축제 4건을 캘린더에 담아 보고, 기상청 API를 직접 조회해 실제로 비 예보(강수확률 60%)인지 맞춰 봄

배포하니 우천 경고가 아예 동작 안 함

원인이미 인코딩된 기상청 키를 RestTemplate이 한 번 더 인코딩해서 403

해결완성된 URI 객체로 넘김

내 PC에서만 mvnw spring-boot:run 실패11월

원인플러그인이 클래스패스 파일을 UTF-8로 쓰는데 윈도우 Java는 MS949로 읽어서, 한글이 들어간 사용자 폴더 경로가 깨짐. 플러그인 코드를 직접 열어 보고 알아냄

해결이 문제가 고쳐진 플러그인 버전(3.3.6)만 지정

배포에서만 설정 저장, 알림 읽음이 안 됨

원인CORS 허용 메서드에 PATCH가 빠져 있었음. 로컬은 Vite 프록시를 거쳐서 문제가 안 보였음

해결추가하고 회귀 테스트 작성

필터 추가했더니 서버가 안 뜸

원인HQL is empty를 바인드 파라미터에 쓸 수 없음

해결비어 있는지 여부를 서비스에서 미리 계산해서 boolean으로 넘김

권한 확인이 빠진 API

원인관리자 동기화 API에 권한 확인이 없었고, 관리자 계정을 만들 수 있는 안 쓰는 API가 열려 있었음

해결권한 확인 추가, 안 쓰는 API 삭제, 이후 토큰 인증으로 통일

아직 못 한 것

  • 기상청 단기예보라 오늘~모레까지만 판단하고, 경고는 화면 배너라 푸시 알림은 아닙니다.
  • 비밀번호 변경·찾기가 없습니다.
  • Render 무료 DB가 30일 뒤 만료돼서, 상시 데모를 하려면 DB를 다시 만들거나 유료로 바꿔야 합니다.
로컬에서는 잘 되다가 배포하면 안 되는 문제(CORS, 키 이중 인코딩)를 여러 번 겪었습니다. 우천 경고는 화면만 있고 실제로는 한 번도 안 뜨고 있었는데 한참 뒤에야 알았습니다. 그 뒤로는 고치고 나서 실제 데이터로 한 번 더 확인합니다.
